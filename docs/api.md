## `@jsx6/signal`

Signals are functions: call with no argument to read, with a value to write.

- creation/interop: `signal`, `prepareSignal`, `staticSignal`, `asSignal`, `signalValue`,
  `isObservable`
- subscription: `observe`, `observeNow`, `subscribe`, `subscribeSymbol`, `triggerSymbol`
- derived: `$S`, `$F`, `$If`, `$Map`, `$Any`, `$AnyValue`, `$And`, `$AndB`, `$Or`, `$OrB`,
  `$EQ`, `$EQX`, `$NEQ`, `$NEQX`, `$NOT`, `$BOOL`
- computed: `$C` (lazy, memoized, auto-tracking), `$CE` (eager), `batch`, `dispose`
- filters used with `$F`: `VALUE`, `EQ`, `EQX`, `NEQ`, `NEQX`, `NOT`, `BOOL`
- from `src/state.js` / `src/makeContext.js`: `$State`, `mergeValue`, `makeContext`, …

**Contract worth knowing:** `$S`/`$F` are eager and their dependency set is the **union** of the declared
list and the reads tracked while the callback runs, so an omitted dependency is no longer a silent bug
(the `jsx6/signal-dependencies` rule is now a style guide). They still recompute on every dependency
change; `$C` is the lazy, memoized alternative and `$CE` the eager one. Notification remains
value-guarded (`===`), so an unchanged value never wakes a listener, and `batch()` removes the
intermediate values a multi-source update would otherwise expose. Signals and computeds also carry a
non-enumerable `value` getter for dev-console inspection. The full design, implementation and change
record is documented in [libs/signal/doc/computed/](../libs/signal/doc/computed/README.md) — starting
with [usage](../libs/signal/doc/computed/usage.md) and
[changes](../libs/signal/doc/computed/changes.md).

## `@jsx6/jsx6`

`index.js` re-exports the whole `src/` surface. The pieces most consumers use:

- DOM creation: `h`, `toDom`, `domWithScope`, `insert`, `forInsert`, `factories`, `changeFactories`,
  `toDomNode`, `updateTextNode`
- attributes/values: `setAttribute`, `getAttr`, `getAttrBoolean`, `setAttrBoolean`, `setValue`,
  `getValue`, `setEnabled`, `setSelected`, `setVisible`, `isVisible`, `addClass`, `classIf`
- directives: `addDirective`, `getDirective`, `x-if`, `x-else`, `x-enabled`, `x-disabled`,
  `x-readonly`, `x-value`, `x-filter`
- components: `Jsx6` (component wrapper), `Jsx6old` (**deprecated** legacy model — see P3-2),
  `HiddenInput`, `mapProp`
- lists: `Loop`, `LoopItem`
- lifecycle: `disposeNode`, `addDisposer`, `jsxDisposeSymbol` — see
  [disposal-design.md](../plan/disposal-design.md)
- events: `fireEvent`, `fireCustom`
- forms/validation: `linkForm`, `form`, `validate`
- i18n: `trans`, `addTranslations`, `errTranslations`
- errors: `throwErr`, `errorMessage`, `errorCodes.js` (`JSX6E*` numeric codes, so message strings stay
  out of production bundles)

`Loop` reconciles by index; `key`/`loopKey` are stored but deliberately not yet read — see
[keyed-loop-design.md](../plan/keyed-loop-design.md).

## `@jsx6/w`

`index.js` re-exports `src/JsxW.js` and `src/Loop.js`: `JsxW`, `JsxWS`, `define`, `Loop`, `LoopItem`.
This is the canonical component model (P3-2).

## `@jsx6/signal-clock`

`getClockSignal`, `getClockSignalDate`, `getClockSignalSeconds`, `initClockSignal`, `stopClock`,
`isClockRunning`, `withClockTime`, `toMs`, `toSeconds`, `$DurationSignal`,
`$DurationSignalSeconds`.

## `@jsx6/url-util`

`urlBool`, `urlGet`, `urlGetBool`, `urlInit`, `urlInitBool`, `urlSet`, `urlStr`, `urlReplace`,
`urlReload`, `refreshUrl`, `setUrl`. The location is read lazily; call `refreshUrl()` after a
client-side navigation and `setUrl()` to work outside a browser or in tests.

## Apps

`@jsx6/repl` and `@jsx6/nodditor` are applications that are also published because the tutorial and
the editor are consumed from npm. They are part of the lockstep version group (see
[MODULE_VERSIONING.md](../MODULE_VERSIONING.md)); their public surface follows their `index.js` /
built bundles rather than a stable library API.
