WebGPU (@jsx6/line-render) · PixiJS 8 · native SVG — identical edges, identical world-space grid, one shared pan/zoom. If the implementations are right, all three panels overlap pixel for pixel.
WebGPU — one instanced triangle-strip draw
PixiJS 8 — WebGL Graphics stroke paths
SVG — browser-native <path> 


    

      All three panels draw the same cubic Bezier edges under the same viewport (screen = world * zoom + pan).
      The GPU side samples each curve at 32 points and extrudes the width along the tangent normal; the PixiJS side
      draws one Graphics stroke path per edge inside a container at x = panX, y = panY, scale = zoom.
      By default the width is in world units, so the thickness scales with zoom in all three panels. The two checkboxes
      toggle the lines and the grid between world-unit width and zoom-independent screen-pixel width (the SVG side
      mirrors the switch with vector-effect="non-scaling-stroke"; PixiJS has no non-scaling stroke, so the
      bridge divides the width by zoom). "exact pick" switches hover/click between the default 8 screen-pixel tolerance
      (easy to pick thin lines in a graph) and picking only exactly on the stroke. Hover/click uses the shared pure
      pickEdge in all three panels — the same function a PixiJS migration keeps unchanged.
      Wheel = zoom at cursor · drag = pan · hover = highlight · click = pick (reported in the readout).
