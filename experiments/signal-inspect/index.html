How console.log($sig) is made readable. A signal is a function, and Chrome renders a function value as a clickable source snippet: it lists none of the function's own properties and does not run custom formatters for it. So no property on a signal — and no formatter — can make a bare signal readable there.

This page uses installConsoleInspection(): the console methods are wrapped, so a signal argument is replaced by a described object ({signal, kind, value, read, raw}). Your call site does not change, there is no cost on any signal read or write, and nothing needs enabling. It stays opt-in in real projects, because it patches global console methods. The wrapper is what DevTools attributes each entry to, so showCallSite: true appends the real (logged from …) location, and console.log.original is kept.

A proxy handle per signal would let DevTools' own formatters read it — that was built and measured at +1208 % on a 2M write+read loop and +2373 % on computed reads, so it was removed rather than shipped behind a flag. The zero-mechanism fallback always works: console.log($count.value), the non-enumerable getter, or demo.describe($count) for the described object by hand.

What to try in the console

  1. console.log($count), console.log($double), console.log($user) — as written, and each shows {signal, kind, value, read, raw} with the value.
  2. Press toggle console inspection to see the difference: with it off, a signal logs as the function it is (function source in Chrome).
  3. Press log a snapshot and the signal, then write $count a few times, then expand the earlier log entry: the snapshot stays at the old number, the signal entry shows the current one. That is the difference between console.log($count()) and console.log($count).
  4. Press print enumeration facts: value is non-enumerable, so Object.keys, spread and JSON.stringify never see it. (get is enumerable — that is pre-existing.)
  5. Try core.signal(5) then expand what it returns; or core.$C(() => $count() * 100) for a computed created from the console.
  6. Press create a cyclic computed and read it: the guard returns the previous value and reports the cycle once, instead of hanging or overflowing the stack.
  7. Inspect $user (a $State): it is a proxy, so read fields as $user.name.value, or the snapshot as $user().
  8. $static is a staticSignal and deliberately has no value — describeSignal still reads it (it calls the signal), so compare its entry with $count's.

Other globals: core (the active core module), cores (both cores), signals (every demo signal by name), demo (the small API this page uses).
